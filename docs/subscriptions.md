# Подписки

Подписка: HTTPS-адрес, по которому приложение получает список серверов. Приложение само обновляет список и настройки серверов из подписки. Сервер подписок в этот репозиторий не входит: подойдёт любой HTTPS-сервер, который отдаёт ответ в описанном ниже формате.

Встроенная подписка сервера TrustTunnel (`[subscription]` в `vpn.toml`, JSON по HTTP Basic Auth) устроена иначе, и приложение её не читает.

## Формат ответа

Тело ответа: ссылки `tt://`, по одной на строку, в том же формате, что при экспорте одного сервера ([DEEP_LINK.md](https://github.com/Cattunnel/cattunnel-server/blob/main/DEEP_LINK.md), включая расширенные теги CatTunnel).

```text
#mirrors https://sub1.example.com/s/<токен> https://sub2.example.com/s/<токен>
tt://?<payload сервера 1>
tt://?<payload сервера 2>
```

- Строка `#mirrors` необязательна. В ней через пробел перечислены зеркала этой подписки в порядке опроса, только `https://`. Она заменяет сохранённый список, так что сервер может добавлять, переставлять и убирать зеркала. Старые версии приложения её пропускают.
- Остальные строки, которые не начинаются с `tt://`, пропускаются.
- Ответ без единой ссылки `tt://` считается ошибкой, а не командой удалить все серверы.

## Шифрование

Ответ может быть зашифрован [age](https://age-encryption.org/v1) (X25519), в бинарном виде или в ASCII armor. Приложение расшифровывает его на устройстве.

- **Ключ устройства.** При первом запуске приложение создаёт свой ключ age и больше его не меняет. Закрытая часть не покидает устройство: на Android она хранится зашифрованной ключом из Android Keystore, на Windows через DPAPI, на Linux в файле с правами 0600. Открытая часть (`age1…`) уходит серверу в заголовке запроса, и сервер шифрует ответ под неё. Поэтому утёкший адрес подписки другому устройству ничего не даёт.
- **Ключ в подписке.** Можно также задать подписке закрытый ключ `AGE-SECRET-KEY-1…` вручную; так работают подписки, выданные до появления ключа устройства.

Библиотека age для Dart лежит в `packages/dage`: в ней исправлены две несовместимости со спецификацией age (соль HKDF для MAC заголовка и формат grease-строф), без них не открывались подписки, зашифрованные эталонной реализацией.

## Запрос

- Только `https://`, перенаправления не выполняются: ответ содержит логины и пароли.
- `GET` с заголовками `User-Agent: CatTunnel/<версия>`, `x-device-key` (открытый ключ устройства), `x-hwid` (случайный идентификатор устройства, не секрет), `x-device-os`, `x-device-model`, `x-ver-os`, `x-app-version`.
- На соединение с одним зеркалом и заголовки ответа отводится 7 с, на чтение тела 20 с. Ответ больше 4 МБ отбрасывается. При кодах 408, 429 и 5xx запрос к зеркалу повторяется.
- Зеркала опрашиваются по порядку до первого ответа 200.

## Одноразовые коды

Вместо постоянного адреса можно передать одноразовый код: ссылкой из браузера, QR-кодом или картинкой из галереи. Приложение отправляет `POST <base>/api/ct/exchange` с JSON `{code, device_key, device_id, platform, model, os_version}` и получает `{subscription, mirrors}`: постоянный адрес подписки и зеркала, уже привязанные к ключу устройства. Код сгорает после обмена.

## Обновление

```text
 зеркало 1 --нет ответа--> зеркало 2 --200--> ответ
   -> расшифровка ключом устройства (age)
   -> ссылки tt:// -> сверка по именам внутри подписки:
      новые добавить, пропавшие убрать, выбранный не трогать
   -> значения ссылок записать в ключи (кроме «Выше подписки»)
```

- Серверы сверяются по имени в пределах своей подписки: новые добавляются, пропавшие удаляются. Выбранный сейчас сервер не удаляется, пока он выбран.
- Перед подключением приложение обновляет подписку, если она не обновлялась 24 часа. Подключение ждёт обновления не больше 4 секунд; после неудачи такая попытка не повторяется час. Обновить вручную можно в любой момент.
- Под подпиской видно, когда она обновилась, через какое зеркало и за сколько, а при неудаче, сколько зеркал не ответило. По нажатию открывается список попыток: адрес без пути, итог (HTTP 200, код ошибки, таймаут, нет соединения, ошибка TLS, расшифровка не удалась) и время. Токен подписки не записывается. Тот же список попадает в экспорт логов файлом `subscription_polls.log`.

## Подписка главнее ключа

При каждом обновлении подписка записывает в свои ключи все значения ссылки, в том числе выключенные переключатели: способ анти-DPI, отпечаток TLS, маскировку размеров, отключение QUIC, NineLives и остальное. Если тега в ссылке нет, остаётся значение приложения.

Чтобы настроить ключ из подписки по-своему, включите «Выше подписки» в разделе «Для экспертов». Такой ключ подписка больше не трогает; он помечается «Ключ отличается от серверного», а кнопка «Вернуть как на сервере» возвращает значения подписки.

## Имя сервера и отпечаток по пользователям

Подписка может выдать разным пользователям разные имена одного сервера (тег `0x03`, свой SNI) и разные профили TLS (тег `0x42`), а со временем менять их. Приложение просто использует то, что пришло в последнем обновлении. Серверу для этого нужно принимать все имена (`allowed_sni` в [сервере CatTunnel](https://github.com/Cattunnel/cattunnel-server/blob/main/docs/features.md#several-server-names-sni-rotation)) с сертификатом, который их покрывает: строгая проверка сертификата в приложении иначе не пропустит соединение.
