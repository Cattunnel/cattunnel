# NineLives

NineLives: второй транспорт CatTunnel, рядом с обычным `CONNECT`. Нужен [сервер CatTunnel](https://github.com/Cattunnel/cattunnel-server) с включённым NineLives или другой сервер с его поддержкой. Включается в настройках сервера, раздел «Для экспертов», или подпиской.

С XHTTP из Xray NineLives не совместим: у него своя разметка кадров, своё шифрование тела и своё восстановление сессии, ссылки и конфигурации Xray он не принимает. Слово `xhttp` в ключах настроек осталось от рабочего названия.

## Как устроен

- Одно соединение приложения идёт не потоком `CONNECT`, а парой запросов HTTP/2 на один путь: `GET`, в ответе на который идут данные к устройству, и `POST`, в теле которого идут данные к серверу. Данные разбиты на кадры с номерами байт и подтверждениями.
- **Шифрование тела.** Если в ключе есть открытый ключ сервера, клиент начинает с рукопожатия: одноразовый ключ X25519, ответ сервера со своим одноразовым ключом и подписью Ed25519, из общего секрета HKDF-SHA256 выводит отдельный ключ AES-128-GCM для каждого направления. Подпись клиент проверяет по открытому ключу сервера, поэтому посредник с поддельным сертификатом не может прочитать тело. Ошибка рукопожатия или расшифровки никогда не переводит сессию на открытое тело. Без ключа сервера (или с выключенным переключателем шифрования) тело защищено только TLS.
- **Продолжение после обрыва.** Сервер выдаёт сессии токен. Если соединение оборвалось, клиент открывает новую пару запросов с тем же идентификатором сессии и доказывает владение токеном (HMAC по свежему вызову сервера). Сервер досылает неподтверждённые данные. Сессия ждёт продолжения до 60 секунд (настройка сервера).
- **Память.** Сервер держит буферы NineLives в общем бюджете памяти. Если места нет, новая сессия получает отказ 503, а работающие не вытесняются.

Протокол на проводе: [docs/xhttp-protocol.md](https://github.com/Cattunnel/cattunnel-server/blob/main/docs/xhttp-protocol.md) и [docs/ninelives.md](https://github.com/Cattunnel/cattunnel-server/blob/main/docs/ninelives.md) в репозитории сервера.

## Настройки ключа

| Настройка | Ключ ядра | Тег `tt://` |
|---|---|---|
| NineLives вместо CONNECT | `xhttp_enable` | `0x4F` |
| Путь запросов (пусто = `/api/v2/`) | `xhttp_path` | `0x50` |
| Открытый ключ сервера Ed25519, base64, 44 символа | `xhttp_server_key` | `0x51` |
| Шифрование тела (локальный переключатель) | ключ передаётся ядру, только если он включён | нет |

Ключ сервера обычно приходит из подписки. Переключатель шифрования хранится только на устройстве: при выключенном переключателе ключ остаётся сохранённым, но ядро его не получает.

## Состояние

NineLives вышел в 1.5.9 вместе с продолжением сессии до 60 секунд. Форма трафика (размеры и ритм кадров по сравнению с браузером) ещё дорабатывается, поэтому в следующих версиях протокол может измениться. В роутерной редакции NineLives пока не настраивается.
