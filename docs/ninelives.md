# NineLives

NineLives: второй транспорт CatTunnel, рядом с обычным `CONNECT`. Нужен [сервер CatTunnel](https://github.com/Cattunnel/cattunnel-server) с включённым NineLives или другой сервер с его поддержкой. Включается в настройках ключа, раздел «Для экспертов», переключатель «Транспорт NineLives», или подпиской.

С XHTTP из Xray NineLives не совместим: у него своя разметка кадров, своё шифрование тела и своё восстановление сессии. Ссылки и конфигурации Xray он не принимает. Слово `xhttp` в ключах настроек осталось от рабочего названия. Протокол на проводе: [protocols.md](protocols.md) и документы сервера [xhttp-protocol.md](https://github.com/Cattunnel/cattunnel-server/blob/main/docs/xhttp-protocol.md) и [ninelives.md](https://github.com/Cattunnel/cattunnel-server/blob/main/docs/ninelives.md).

## Как устроен

```text
 приложение                                   сервер
   GET  /путь/SID   <---- данные к устройству ----
   POST /путь/SID   ----- данные к серверу ----->
   кадры с номерами байт и подтверждениями,
   тело зашифровано AES-128-GCM (если есть ключ сервера)

 обрыв:
   новая пара GET/POST с тем же SID и доказательством владения токеном
   -> сервер досылает неподтверждённое (ждёт до 60 с)
```

Рисунок 1. Сессия NineLives и её продолжение после обрыва.

- Одно соединение приложения идёт не потоком `CONNECT`, а парой запросов HTTP/2 на один путь: `GET`, в ответе на который идут данные к устройству, и `POST`, в теле которого идут данные к серверу. Данные разбиты на кадры с номерами байт и подтверждениями. Много сессий делят одно TLS-соединение, а само TLS-соединение берётся из того же пула, что и для `CONNECT` ([anti-dpi.md](anti-dpi.md#пул-соединений)).
- **Шифрование тела.** Если в ключе есть открытый ключ сервера, клиент начинает с рукопожатия: одноразовый ключ X25519, ответ сервера со своим одноразовым ключом и подписью Ed25519, затем HKDF-SHA256 выводит из общего секрета отдельный ключ AES-128-GCM для каждого направления. Подпись клиент проверяет по открытому ключу сервера, поэтому посредник с поддельным сертификатом не может прочитать тело. Ошибка подписи, обмена ключами или расшифровки никогда не переводит сессию на открытое тело. Без ключа сервера (или при выключенном переключателе «Шифрование NineLives») тело защищено только TLS.
- **Продолжение после обрыва.** Сервер выдаёт сессии токен. Если соединение оборвалось, клиент открывает новую пару запросов с тем же идентификатором сессии и доказывает владение токеном (HMAC по свежему вызову сервера). Сервер досылает неподтверждённые данные. По умолчанию сессия ждёт продолжения 60 секунд (настройка сервера `xhttp_resume_timeout`).
- **Память.** Сервер держит буферы NineLives в общем бюджете памяти. Если места нет, новая сессия получает отказ 503, а работающие не вытесняются.

## Настройки ключа

| Настройка | Ключ ядра | Тег `tt://` |
|---|---|---|
| Транспорт NineLives вместо CONNECT | `xhttp_enable` | `0x4F` |
| Префикс пути (пусто означает `/api/v2/`) | `xhttp_path` | `0x50` |
| Открытый ключ сервера Ed25519, base64, 44 символа | `xhttp_server_key` | `0x51` |
| Шифрование NineLives (локальный переключатель) | ключ передаётся ядру, только если переключатель включён | нет |

Путь должен начинаться с `/`. Ключ сервера обычно приходит из подписки. Переключатель шифрования хранится только на устройстве: при выключенном переключателе ключ остаётся сохранённым, но ядро его не получает. Если в настройках ядра включено шифрование тела (`xhttp_body_encryption = true`), ему нужен действительный ключ сервера из 32 байт, иначе ядро отказывается принять настройки.

## Совместимость с другими возможностями

- **Ротация IP** работает только с `CONNECT` по HTTP/2. Пока включён NineLives, ключ остаётся на своём адресе ([rotation.md](rotation.md)).
- **CatTail** (шумовая маскировка, настройки ключа «Маскировка») тоже работает только с `CONNECT`. С включённым NineLives соединение идёт тихо, как в обычном режиме.
- В роутерной редакции NineLives пока не настраивается.

## Состояние

NineLives вышел в 1.5.9 вместе с продолжением сессии до 60 секунд. Форма трафика (размеры и ритм кадров по сравнению с браузером) дорабатывается, поэтому в следующих версиях протокол может измениться.
