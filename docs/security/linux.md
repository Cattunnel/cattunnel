# Linux: безопасность (исправления)

Здесь разобраны находки внутреннего аудита десктопных клиентов, сделанного на сборке Linux 1.4.5: список и итоги в [KNOWN-ISSUES.md](KNOWN-ISSUES.md). Все исправления из этой таблицы присутствуют в коде 1.5.9.5. Устройство помощника и его протокол: [plugins/vpn_plugin/linux/HELPER.md](../../plugins/vpn_plugin/linux/HELPER.md).

От root на Linux работает только небольшой помощник `cattunnel-helper` (исходники в `plugins/vpn_plugin/linux/helper/`) и клиентское ядро, которое он запускает. Приложение работает от обычного пользователя и говорит с помощником через сокет `/run/cattunnel/helper.sock`.

```text
 приложение (пользователь)
        |  сокет /run/cattunnel/helper.sock, группа cattunnel
        v
 cattunnel-helper (root)
   |-- проверка клиента: SO_PEERCRED, группа
   |-- проверка конфига: белый список ключей и типов (config_guard)
   |-- запуск ядра trusttunnel_client по фиксированному пути
   |-- подмена DNS на время сеанса, откат при остановке
   '-- relay / probe: диагностика мимо туннеля
```

Рисунок 1. Что делает помощник и где стоят проверки.

| # | Проблема | Исправление | Где в коде |
|---|----------|-------------|------------|
| 1 | Поле JSON неверного типа (`{"cmd":1}`) роняло помощник от root (необработанное исключение, SIGABRT) | `Str` и `Int`: неверный тип означает «поля нет», числа зажаты в диапазон; разбор запроса обёрнут в try/catch | `helper/main.cpp` |
| 2 | «Молчащий» клиент вешал единственный цикл помощника (`ReadLine`) | `SO_RCVTIMEO` 5 с на принятых сокетах (у relay и probe снимается) | `helper/main.cpp`, `kReadTimeoutSeconds` |
| 3 | Белый список конфига пропускал `[[listener.socks]]`, массивы вместо строк, вложенные таблицы | схема с типом каждого ключа; `[listener.socks]` только с адресом на loopback | `helper/config_guard.cpp`, тест `CheckConfig.RefusesOtherShapesAndTypes` |
| 4 | Лог `/var/log/cattunnel/client.log` рос без ограничения | больше 8 МиБ: файл переименовывается в `client.log.1` (одна ротация); копия в памяти до 2 МиБ | `helper/cli_runner.cpp` |
| 5 | Потоки relay и probe без лимита | не больше 32 одновременно; в юните `TasksMax=64`, `LimitNOFILE=1024` | `helper/main.cpp`, `linux/packaging/cattunnel-helper.service` |
| 6 | Ошибка DNS не останавливала подключение (fail-open) | при `start` без подмены `resolv.conf` («DNS NOT SET») ядро останавливается, DNS откатывается, приложению возвращается ошибка | `helper/main.cpp`, `helper/system_dns.cpp` |
| 7 | Обновление пакета не перезапускало помощник | `post_upgrade`: `daemon-reload` и перезапуск, если VPN сейчас не поднят; иначе подсказка | `linux/packaging/cattunnel.install` |
| 8 | Экспорт логов в предсказуемый каталог `/tmp/cattunnel_linux_logs_<время>` | `g_dir_make_tmp`: случайное имя, права 0700 | `plugins/vpn_plugin/linux/vpn_plugin.cc` |
| 9 | HELPER.md расходился с кодом | исправлено: строка до 1200 КиБ, лог с правами 0600, лимиты, fail-closed | `plugins/vpn_plugin/linux/HELPER.md` |
| 10 | Нет «владельца» сеанса: любой участник группы мог остановить чужой туннель, заменить его своим или прочитать лог | владелец это пользователь, запустивший туннель. `stop`, `logs` и `start` поверх работающего туннеля доступны только владельцу и root; при смене владельца лог в памяти очищается | `helper/main.cpp`, `IsOwner` |
| 11 | relay и probe вели на любой адрес мимо чужого туннеля | пока туннель поднят, они доступны только владельцу и root. Без туннеля обходить нечего, диагностика работает как раньше | `helper/main.cpp` |

**Открыто.** Владелец сеанса сам может через relay и probe выйти на любой адрес мимо своего туннеля: так задумана диагностика Марсика (проверка серверов и опорных адресов). Лог на диске (`/var/log/cattunnel/client.log`, root, 0600) общий для всех сеансов.
