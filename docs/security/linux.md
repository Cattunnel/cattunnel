# Linux: безопасность (исправления)

Источник: внутренний аудит безопасности (run-2), список `KNOWN-ISSUES.ru.md`. Исправлено 30.09.2026, до выпуска 1.4.5.

| # | Проблема | Исправление | Проверка |
|---|----------|-------------|----------|
| 1 | Поле JSON неверного типа (`{"cmd":1}`) роняло root-помощник (`type_error` → SIGABRT) | `Str`/`Int` в `helper/main.cpp`: неверный тип = поле отсутствует, числа зажаты в диапазон; `Handle` в try/catch | вручную: `{"cmd":1}`, `"max":"x"`, `timeout_ms:-5` → штатные ответы, помощник жив |
| 2 | «Молчащий» клиент вешал единственный цикл помощника (`ReadLine`) | `SO_RCVTIMEO` 5 с на принятых сокетах (у relay/probe снимается) | вручную: недописанная строка → следующий клиент обслужен через 5,0 с |
| 3 | Белый список конфига пропускал `[[listener.socks]]`, массивы вместо строк, вложенные таблицы | `config_guard.cpp`: схема с типом каждого ключа; `[listener.socks]` только с loopback-`address` | `helper_tests` `RefusesOtherShapesAndTypes` |
| 4 | Лог `/var/log/cattunnel/client.log` без ограничения | > 8 МиБ → `client.log.1` (один файл ротации) | код, `cli_runner.cpp` |
| 5 | Потоки relay/probe без лимита | не больше 32 одновременно; в юните `TasksMax=64`, `LimitNOFILE=1024` | код |
| — | Ошибка DNS не останавливала подключение (fail-open) | `start`: если resolv.conf не подменён («DNS NOT SET») — CLI останавливается, DNS откатывается, приложению ошибка | живая проверка 30.09: `chattr +i` → старт отменён, resolv.conf цел |
| — | Обновление пакета не перезапускало помощник | `post_upgrade`: `daemon-reload` и перезапуск, если VPN сейчас не поднят; иначе подсказка | живая проверка 30.09: перезапущен |

| — | HELPER.md расходился с кодом (256 КиБ, 0640) | исправлен: 1200 КиБ, 0600, лимиты, fail-closed | — |

| — | Нет «владельца» сеанса: любой участник группы мог остановить чужой туннель, заменить его своим или прочитать лог | Владелец = uid, запустивший туннель. `stop`, `logs` и `start` поверх работающего туннеля — только владельцу и root; при смене владельца лог в памяти очищается | живая проверка 30.09 на Debian 13 (два пользователя): чужому «another user's session», relay сброшен |
| — | relay/probe вели на любой адрес мимо туннеля | Пока туннель поднят — только владельцу и root (чужой участник группы не выведет трафик мимо чужого туннеля). Без туннеля обходить нечего, диагностика работает как раньше | код |

**Открыто:** владелец сам может через relay/probe выйти на любой адрес мимо своего туннеля — так задумано для диагностики Марсика (серверы, ya.ru). Лог на диске (`/var/log/cattunnel/client.log`, 0600 root) общий для всех сеансов.
