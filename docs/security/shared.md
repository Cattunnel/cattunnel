# Общий код (все платформы): безопасность (исправления)

Здесь исправления общего кода приложения, найденные внутренним аудитом. Пункты 6 и 7 из списка [KNOWN-ISSUES.md](KNOWN-ISSUES.md), остальные добавлены позже. Все они присутствуют в коде 1.5.9.5. Исправления только для Linux: [linux.md](linux.md).

```text
 внешние данные                       что приложение проверяет
 ---------------------------------------------------------------------
 списки российских сетей и доменов -> лимиты охвата, зоны .ru/.su/.рф (п. 6)
 имя, пароль, сертификат сервера   -> экранирование в TOML (п. 7, 11)
 ссылка tt:// и файл конфигурации  -> длина DER, ru_exit, имена (п. 9, 10, 12)
 ответы подписки, манифест, APK    -> лимит размера (п. 13)
 хранилище сертификатов            -> без российских корней (п. 8, 14)
```

Рисунок 1. Что приходит снаружи и где стоит проверка.

## Исправлено в первой группе (пп. 6-7)

| # | Проблема | Исправление | Проверка |
|---|----------|-------------|----------|
| 6 | Российские списки: отравленный IPv6-список мог свернуться в `2000::/3` (весь IPv6 мимо VPN); любые иностранные домены могли стать «российскими» | `lib/data/ru_lists/ru_lists_service.dart`: лимит 1 % от `2000::/3` на источник (3 % IPv4), общий лимит после слияния (5 % IPv4 и 2 % IPv6, иначе секции IP пустые и работают встроенные); домены из скачанных списков только `.ru`, `.su`, `.рф` и короткий проверенный список (`vk.com`, `yandex.net` и другие) | `test/ru_lists_test.dart` (400 сетей /16 отклоняются; `torproject.org` и `protonmail.com` не проходят) |
| 7 | Кодировщик конфига не экранировал строки: кавычка или перевод строки в имени или пароле сервера дописывали в TOML ядра свои ключи | `IniString.encode` в `plugins/vpn_plugin/lib/models/ini_document.dart`: базовая строка с экранированием (`\"`, `\\`, `\n`, управляющие символы как `\uXXXX`); многострочная `"""` только для PEM без опасных символов; декодер и разбор списков понимают экранирование | `plugins/vpn_plugin/test/ini_escape_test.dart` |

## Сертификаты на Windows и Linux

| # | Проблема | Исправление | Проверка |
|---|----------|-------------|----------|
| 8 | На Windows и Linux ядро проверяло сертификат сервера по всему системному хранилищу. Установщик Госуслуг кладёт корень НУЦ («Russian Trusted Root CA») в доверенные корни Windows. Тот, у кого он есть, мог бы подделать сертификат сервера и читать туннель вместе с паролем | `lib/feature/security/domain/desktop_ca_bundle.dart`: корни из хранилища ROOT Windows или из бандла дистрибутива Linux минус «Russian Trusted Root/Sub CA» (поиск в DER), плюс ISRG Root X1 и X2. `SecurityPlatform.systemCaBundle()` отдаёт бандл ядру (`EndpointCaResolver`) и диагностике (`ServerTls`). Переключатель «доверять пользовательским сертификатам» возвращает поведение по умолчанию. На Android то же закрыто через `SecurityChannel.kt` | `test/feature/security/desktop_ca_bundle_test.dart` (российский корень отброшен, ISRG всегда есть) |

Открыто: размер конфига на Linux ограничен 1 МиБ (`plugins/vpn_plugin/linux/helper/config_guard.h`). Если списки и бандл сертификатов вырастут, этот лимит может стать тесным.
