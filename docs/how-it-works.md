# Как устроен CatTunnel

```text
 приложения на устройстве
        |
        v
 системный VPN (tun) ---- российские сети и домены ----> напрямую
        |
        v
 ядро TrustTunnelClient (своя сборка CatTunnel)
        |  2-4 TLS-соединения HTTP/2 (пул), каждое
        |  соединение приложения = поток CONNECT
        v
 сервер CatTunnel / TrustTunnel ---> интернет
```

Рисунок 1. Путь соединения приложения через CatTunnel.

CatTunnel построен на [TrustTunnel](https://github.com/TrustTunnel/TrustTunnel) и его клиенте. Транспорт по умолчанию тот же: HTTP/2 CONNECT поверх TLS. Всё, что добавлено сверху, описано ниже и в отдельных документах.

## 1. Диагностика Марсика

Если VPN не подключился за 10 секунд, Марсик проверяет подключение по шагам.

```text
 вердикт ядра -> сеть -> TCP к серверу -> TLS и SNI -> доступ (ключи, подписка)
 первый проваленный шаг и есть ответ «что сломалось»
```

Рисунок 2. Шаги диагностики.

0. **Что сказало ядро.** Если в последней попытке ядро само увидело, что путь к серверу режут (адрес заморожен, обрыв после фиксированного числа байт, сессия замолчала), это и есть ответ. Пробы приложения добавили бы ещё рукопожатия к тому же имени, а их пачка и запускает заморозку.
1. **Сеть.** Слово системы: на Android проверка сети самим Android. Где его нет, шаг остаётся «не проверен», отдельных пакетов к чужим узлам приложение не шлёт.
2. **Сервер.** TCP к серверу, различает таймаут и отказ.
3. **TLS и SNI.** Рукопожатие с SNI сервера и ALPN `h2` и `http/1.1`. Сервер TrustTunnel молча рвёт чужой SNI, поэтому «ответил» засчитывается только по TLS-alert. При обрыве выносится один вердикт «защищённое соединение режут». Часы устройства оцениваются по сроку действия сертификата самого сервера.
4. **Доступ.** Настоящий `CONNECT` с логином, только к серверу с проверенным сертификатом (ответы 403, 404, 405 и 407 значат, что ключи не подошли). Если ключи подошли, проверяется подписка: 404 означает, что доступ закончился. Подписка проверяется не чаще раза в 5 минут.

Диагностика работает прямо во время подключения: на Android ядро исключает само приложение из туннеля, а на Windows и Linux пробы привязываются к физическому адаптеру.

## 2. Строгая проверка сертификата сервера

- Если в конфиге нет сертификата, ядро проверяет сервер по системному хранилищу. В Android в него входят и **установленные вручную сертификаты**, в том числе корень Минцифры. Его владелец мог бы подменить сертификат сервера и расшифровать туннель вместе с логином и паролем.
- Поэтому серверу без своего сертификата CatTunnel подставляет **системные корневые сертификаты без «Russian Trusted Root/Sub CA»** (`endpoint_ca_resolver.dart`). Российские сертификаты отсеиваются по имени и по SHA-256 отпечатку ключа.
- Сервер со своим сертификатом (PEM) проверяется только по нему.
- Выключить проверку (переключатель «доверять пользовательским сертификатам») можно только после **трёх подтверждений**. Если проверка мешает подключению, Марсик подскажет это сам.

Подробнее про защиту: [security/shared.md](security/shared.md).

## 3. Подписки

- Тело ответа: ссылки `tt://`, по одной на строку. Ответ может быть зашифрован age под ключ устройства или под ключ `AGE-SECRET-KEY-1…` из настроек подписки.
- Серверы сверяются по имени в пределах своей подписки: новые добавляются, пропавшие удаляются, **выбранный сервер не удаляется**.
- Пустой ответ без единой ссылки считается ошибкой и серверы не стирает.
- **Подписка главнее ключа:** при обновлении она записывает в свои ключи все значения ссылки, включая выключенные. Ключ с переключателем «Выше подписки» она не трогает, такой ключ помечается «Ключ отличается от серверного», а «Вернуть как на сервере» возвращает серверные значения.
- Зеркала подписки перебираются по порядку. Под подпиской видно, когда, через какой адрес и за сколько она обновилась. Список попыток (адрес без пути, итог, время) попадает в экспорт логов файлом `subscription_polls.log`, токен подписки не записывается.
- Обновление перед подключением ждёт не больше 4 секунд, после неудачи не повторяется час.
- Библиотека age для Dart лежит в проекте (`packages/dage`): в ней исправлены **две несовместимости** со стандартом age (соль HKDF для MAC заголовка и повторная запись «grease»-строф без искажения).
- Формат ответа, заголовки запроса, одноразовые коды и правила обновления: [subscriptions.md](subscriptions.md).

## 4. «Российские сервисы мимо VPN»: маршруты и скорость

- **Маршруты Android** (трафик вообще не заходит в туннель): только крупные сети встроенного списка, /22 и шире. На **Android 13 и новее** они передаются системе как исключения (`excludeRoute`, патч 0004 Android-движка), и туда идут все сети встроенного списка. На Android 12 и старше система получает «весь интернет минус эти сети»: каждый разрозненный блок стоит около десяти маршрутов, а склеивать соседей нельзя, потому что между ними чужие адреса. Android плохо переносит тысячи маршрутов в одном вызове, поэтому в этом случае берутся только крупные блоки.
- **Исключения ядра**: остальное, то есть мелкие сети встроенного списка, его домены (`*.ru`, `*.рф` и другие) и автосписки (российские сети из runetfreedom/geoip и ipverse/rir-ip, домены из hydraponique/roscomvpn-geosite). Ядро ищет по отсортированному списку, размер ему не важен.
- **Адрес VPN-сервера** из списков всегда вычитается.
- **Быстрый старт.** Автосписки скачиваются параллельно через 30 секунд после подключения и не чаще раза в 20 часов. Сливаются в отдельном isolate и сохраняются готовыми (`ru_lists/compiled.v1`). При подключении файл только читается, адрес сервера вырезается точечно, скачанные правила по одному не разбираются. Для авто-сплита запрашиваются только имена пакетов. В логе строка `Connect prepared in N ms`.
- Скачанные списки проходят проверку правдоподобия: [security/shared.md](security/shared.md).

## 5. Анти-DPI и своё ядро

- Приложение работает на **своей сборке ядра TrustTunnelClient 1.3.0-rc.1** (все ABI Android, Windows, Linux, роутеры) с патчами CatTunnel. В 1.5.9.5 приложение и роутер собраны из одной ревизии ядра (`b59debf4`). Что добавлено: приёмы анти-DPI, маскировка размеров HTTP/2, причины отказа, пул из 2-4 TLS-соединений с паузами между рукопожатиями, профили TLS, ротация IP и транспорт NineLives. Серверу для анти-DPI ничего настраивать не нужно: ClientHello остаётся одной TLS-записью, меняется только то, как он режется на TCP-сегменты.
- Приёмы взяты из [ByeDPI](https://github.com/hufrea/byedpi) (MIT): «срочный» байт, который ядро получателя изымает из потока, и кусок с TTL 1, который теряется на первом маршрутизаторе и потом перепосылается системой. Одиночный «срочный» байт вешает tokio-сервер TrustTunnel, поэтому он всегда идёт в паре с куском TTL 1.
- Свои приёмы и строки, режим «Авто», профили TLS, причины отказа и паузы ядра перед повтором: [anti-dpi.md](anti-dpi.md). Маскировка размеров: [padding.md](padding.md). Ротация IP: [rotation.md](rotation.md). NineLives: [ninelives.md](ninelives.md). Протоколы на проводе: [protocols.md](protocols.md).

## 6. Пинг из соединения

Пока ядро выбирает адрес сервера, оно измеряет время соединения с каждым кандидатом. Когда адрес выбран, ядро поднимает событие `VPN_EVENT_ENDPOINT_PING` со временем выбранного. Отдельной пробы для этого числа нет. Адаптер Android превращает событие в запись `{"cattunnel_ping_ms":N}` (от 0 до 60000), и приложение показывает число рядом с ключом.

```text
 ядро: пинг каждого кандидата -> выбор лучшего -> время выбранного
 ядро:    VPN_EVENT_ENDPOINT_PING {мс} ---------------> адаптер Android
 адаптер: {"cattunnel_ping_ms": N} ------------------> приложение
```
